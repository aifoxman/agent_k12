# 小米平板 AI 学习陪伴 MVP 设计草案

状态：v0.7 设计基线；当前实现与验证进度见 [README](../README.md) 和[实现复盘](implementation-review.md)。依据是[作业陪伴应用脑暴](https://chatgpt.com/share/6ac66c31-3a14-83ec-a3b0-1cbc77c72cec)、[同类产品与家长反馈研究](comparable-products-review.md)及本地 `内部部署资料`、`overseas_ai/ai-marketing/ai-orchestration`、`overseas_ai/ai-gateway` 的现有资料。已确认覆盖幼儿园、小学、初中；试点使用可固定拍到纸面的小米 Pad 6；家长使用独立 Android 手机 App，能远程按需查看实时纸面、画圈标注并语音指导。交互细节见[平板端作业会话](tablet-homework-ux.md)、[家长端设计](parent-app-ux.md)和[双端语音交互](voice-interaction.md)。

## 1. 目标与首批用户

长期产品目标以[教师式学习陪伴准则](teacher-led-learning.md)为基线：在家庭学习中承担优秀辅导老师的读题、分析、方法示范、独立尝试、检验迁移、习惯培养、限时练习和学习反馈等具体工作。每个后续功能均需检查是否帮助孩子形成方法、是否保留独立思考与家长复核，并参照教育研究和同类产品经验；批改只是辅导闭环中的诊断环节。当前 MVP 不把模型回答等同于真人教师效果。

产品面向幼儿园、小学、初中三个年龄段，以家庭作业辅导为首要场景，不预设单一优先科目。设备闭环先以一个家庭、一名孩子、一台可固定拍到纸面的小米 Pad 6 和一部安装家长 App 的 Android 手机验证；年龄适配验收再分别使用三个年龄段孩子的真实家庭作业，不把一个孩子的结果外推到全部年龄段。家长能远程录入、查看并确认任务，按需看纸面直播、画圈并语音指导；孩子在平板上完成作业、请求帮助；双方能看见哪些任务已完成、哪些仍需确认。

三个年龄段共用任务、会话、家长确认和日报，教学交互按年龄分开：幼儿园以真实家庭活动或作业为样本，使用大图标和语音播报，帮助内容为短句鼓励与一步指引；小学使用分级提示；初中允许更完整的推导过程，并加强答案核对。首版需各选一份真实家庭作业做端到端验证，不能把一套数学提示词直接用于所有年龄段。

同类产品反馈显示，快速解决纸面小问题与远程查看有明确需求，误判、频繁提醒和孩子依赖答案也受到批评。首版因此优先缩短“定位当前题目 → 获得一步提示 → 继续作答 → 家长复核”的路径；作业界面只保留任务、纸面状态、求助和暂停，不加入娱乐信息流或与作业无关的陪聊。

作业中的纸面分析可以提供题目进度、书写与可见步骤的候选观察，但“识别到停笔”只能代表可能需要帮助，不能推断孩子不会做、在走神或情绪异常；未写出的解题思路需要询问孩子。作业完成度以任务勾选和家长确认为准，不由摄像头自动宣称完成。

## 2. MVP 功能与用户流程

| 环节 | MVP 行为 | 可验证结果 |
| --- | --- | --- |
| 家长建任务 | 在手机端粘贴群作业文字，核对科目、内容和截止时间后发布；可朗读核对或口述修改 | 平板与手机同步的当日任务清单 |
| 孩子做作业 | 主动点击“开始作业”，在相机预览中调整作业本；纸面可读并确认对应任务后进入作业状态。相机持续开启，平板检测纸面变化并按事件分析题目进度、书写与可见解题步骤；显示相机、分析和暂停状态 | 会话时长、带依据且可纠错的进度观察、适时的陪伴提示 |
| 卡题求助 | 孩子点击或说“求提示”并框选当前题目；“指向纸面说这题／这个字”作为试点原型，先确认识别区域，失败时回退框选、重拍或改文字；低龄儿童使用图标与播报 | 确认后的题目或活动内容 |
| 年龄适配引导 | 幼儿园给简短语音指引；小学、初中按思路、关键步骤、解析逐层请求 | 提示记录、是否仍需家长帮助 |
| 远程查看 | 家长 App 查看任务进度、会话状态、求助记录与待确认项；在作业会话中按需直接打开实时纸面画面，无需孩子逐次确认 | 另一部手机可访问的家庭看板与直播入口 |
| 远程指导 | 家长在实时纸面画面上画圈，标注同步显示于孩子平板，并可发起语音沟通；平板显著提示查看、标注与通话状态 | 一次可开始、画圈、通话、结束并恢复作业的远程指导 |
| 完成与回顾 | 孩子结束作业后查看反馈，修正机器误识别并勾选任务；家长在手机端确认。日报汇总任务状态、学习时长、求助次数、待确认项和需要复查的纸面位置 | 可追溯且可纠错的每日回顾 |

作业状态以纸面摆放与可读性检查为入口门槛；准备页可提示光照、遮挡和取景问题，但不把平板包装成护眼台灯。会话中结合时间、书写变化与题目识别触发分析；疑似卡题时先询问“需要提示吗？”，每题最多主动询问一次，允许忽略和冷却；家长可关闭主动提醒，孩子仍可随时求助。已确认平板可以固定拍到纸面，仍需用真实设备验证识别、翻页、耗电和误触发。画面不可读时暂停相关结论，提示调整纸面并保留主动求助。

首版群作业导入只支持粘贴文字，不接入截图识别、QQ／钉钉群机器人，不自动向班级群发消息，也不生成或上传打卡视频。各科家庭作业都可录入清单，但 AI 引导先以三个年龄段各一份代表性作业验收；语音指令、提示播报与孩子主动口述思路纳入首版，开放式长对话、全科自动批改、学习画像、情绪识别、奖励体系和教师端进入后续讨论。

## 3. 远程纸面直播与指导

直播只在平板的作业会话中提供。家长 App 请求查看 → 服务端验证家庭身份与设备绑定及活跃会话 → 平板直接启动纸面推流 → 家长观看；不等待孩子逐次确认。孩子端在查看或通话开始时播报一次，并持续显示状态，可暂停或结束作业会话。家长可在直播画面上画圈，标注作为同步叠加层显示在孩子的平板预览中，并可发起双向语音；画圈不会实际出现在纸张上。翻页、镜头位置变化或会话结束时清除旧标注。直播结束、作业会话结束或网络断开后，短时凭证失效；不默认录制，也不把连续画面送入大模型。

推荐使用 [WebRTC 点对点连接](https://webrtc.org/getting-started/peer-connections)传输音视频，由专用 API 提供鉴权、信令和会话状态；跨网络连通需准备 [STUN／TURN](https://webrtc.org/getting-started/turn-server) 与短时 TURN 凭证。现有 `3.6.env.md` 未列出 TURN，不能把 AI Orchestration、RustFS 或 Xray 当作现成视频中继。直播重视纸面文字可读性：先以自适应画质展示整体桌面，必要时由家长请求一张临时高清定格图；画质、延迟与流量须用平板 Wi-Fi、家长手机蜂窝网络实测。

平板只建立一个相机采集源，再将画面用于取景预览、本地质量及变化检测、事件截图和直播；不得由两个模块各自抢占相机。[CameraX 可以组合预览、分析和采集用例](https://developer.android.com/media/camera/camerax/architecture)，但可用分辨率与性能依设备而异，目标小米平板必须实测。启动相机和麦克风还要遵守 [Android 前台服务与后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)：家长请求不能绕过平板端的可见会话与系统权限。

## 4. AI 处理与模型选择

已确认作业会话可按事件上传裁剪后的纸面图像到服务端，并可由服务端转发给符合数据处理要求的第三方模型，包括首次识别、翻页、书写进展、疑似卡题、疑似做完与主动求助；连续视频不作为模型输入。流程为：本地图像质量检查与事件筛选 → 裁剪必要区域 → 服务端 OCR／视觉分析 → 对题目、字迹和步骤生成带依据及不确定性的候选观察 → 孩子或家长修正 → 按年级、已知教材和年龄段生成结构化引导 → 服务端检查格式、适宜难度及首层是否泄露答案 → 返回 App。纸面没有显示思路时，先询问孩子当前想到哪一步，再给一个可继续尝试的问题；没有可靠参考答案时不自动判对错，缺少教材信息时不宣称“同步教材”。题意或图片不清楚时明确要求重拍／改文字；不凭空补题。画面只能支持对可见书写步骤的分析，未写出的想法要询问孩子；提示不贴能力或心理标签。接入前须核对模型服务商的数据保留与删除条件是否满足本产品的60 天规则。

模型按能力分路由：低成本模型处理题目提取和普通提示，复杂推理模型处理确有需要的题目；具体型号在真实题目样本上比较中文识别、数学正确性、循序引导、延迟、成本及数据处理条件后确定。分享对话里的型号与“80/20”“节省 90%”仅作为脑暴，不作为采购或性能结论。模型凭据只存在服务端，平板不直连模型网关。

## 5. 技术架构与现有服务复用

```text
小米平板 App（学习、相机、语音） ─┐
                                ├→ 家庭学习 API（账号、任务、提示、会话、信令）
家长手机 App（看板、直播、指导） ─┘       ├→ 模型网关适配层 → 可用模型入口
                                        └→ 独立业务库（可复用 PostgreSQL 基础设施）
            两端另通过 WebRTC 传音视频，直连失败时走 TURN 中继
```

平板端与家长端是两个独立的 Android App；两端倾向原生 Android，共用接口契约及可复用的网络代码。平板端负责相机、本地质量与变化检测、事件截图和儿童交互，服务端负责纸面语义分析与引导，家长端负责看板、直播与指导。服务端倾向 Python API，复用现有 Python 经验。平板与手机通过家庭账号及一次性设备配对码关联，家长和孩子使用不同权限；任务进度由服务端同步。家长不在局域网时须通过受鉴权的 HTTPS 业务入口访问，不能直接暴露 `192.168.x.x` 的数据库或内部端口。直播还需要公网可达的信令入口及 TURN 服务，其部署、带宽和费用单独评估。iPhone 家长端不在首版范围。

`3.6.env.md` 记录了 PostgreSQL、Redis、RustFS、Temporal 和 AI Orchestration 的部署资料，但其状态记录日期为 2026-07-27，集成前需验证现状。`ai-gateway` 仓库有 LiteLLM／New API 的配置和模型映射；现有服务清单未给出可直接用于本 App 的网关地址、鉴权契约或儿童数据处理条件。`ai-orchestration` 的公开文档主要面向任务编排，不假定它已经提供教育问答接口。首版采用独立业务 API；Redis、RustFS 和 Temporal 只在出现明确的缓存、留存或异步任务需求时接入，不复用其他业务表或公开桶。

初步接口为 `POST /v1/families/pair`、`POST /v1/tasks/import`、`POST /v1/sessions`、`POST /v1/sessions/{id}/observations`、`POST /v1/sessions/{id}/finish`、`POST /v1/hints`、`PATCH /v1/tasks/{id}`、`GET /v1/families/dashboard`、`GET /v1/reports/daily` 和 `POST /v1/live-sessions`；信令使用鉴权后的实时通道，并同步画圈标注事件。核心数据为家庭、孩子及年龄段、设备绑定、任务、学习会话、带依据与纠错状态的纸面观察、提示请求、直播会话与确认事件；日报由任务及确认事件生成，保留“谁确认完成”的来源。家长看板通过短周期刷新或事件流同步状态；直播视频与通话音频不进入业务库。

## 6. 隐私、安全与试点验收

实现补充：孩子主动批改属于单独的数据路径。孩子只打开“批改作业”；系统在纸面稳定后识别一页或双页、自动裁剪并尝试读取科目和页码，翻页后继续收集。单页核对缩略图后可直接确认，多页核对页数后一次确认；家长授权后逐页返回已答题的批改及解题分析。密集竖版页面会在服务端分区放大分析，合并回原图标记；每页结果只绑定该页截图供家长复核。未识别内容明确标为待识别或无法判断，截图默认60 天清理；其他自动观察图仍只处理当前请求。家长对当前会话授权 10 分钟，可提前撤销。

相机在未开始时关闭，孩子点击“开始作业”后于准备页开启预览，通过纸面检查后在作业状态持续开启；暂停或结束时停止分析与直播。家长在活跃作业会话中可直接打开直播，无需孩子再次确认；孩子端持续显示相机、查看、标注与通话状态，各状态启动时播报一次，并可暂停或结束会话。直播只向已绑定且通过鉴权的家长 App 开放，按需传输，不默认录制。两端语音指令只在按住说话时开启麦克风；家长主动接通通话后双方持续传音，结束通话即停麦，通话时暂停孩子端按键语音指令与 AI 播报。自动观察只按事件上传必要的裁剪图，处理后不持久存储；主动批改则上传当次完整纸面截图，并与该页结果共同保存60 天。任务文字、纸面观察、提示与确认记录、日报及必要的语音指令文本从创建起默认保留60 天，到期自动删除，家长可提前删除。原始语音与直播视频不保存；日志不记录图片、完整题目、音视频或身份信息。第三方模型只接收当前请求所需的纸面图像，选型时验证其数据保留条件；凭据不得从 `3.6.env.md` 复制进仓库、客户端或设计文档。

试点验收先按一个家庭的小米 Pad 6 与另一部 Android 手机完成设备闭环，再分别用幼儿园、小学、初中孩子的真实家庭作业检查年龄适配；摆放不当时不能误入“正在分析”，翻页后能重新定位题目，框选求助可纠错，“指向这题”原型失败时能回退框选，完成后能生成可复查反馈。手机在蜂窝网络中能查看、确认及直接接通纸面直播、画圈标注和语音指导；标注位置在双端一致且孩子能看清，翻页后清除；直连失败时能经 TURN 建立连接或给出明确失败提示；直播结束后不能继续访问；事件分析与推流同时运行时不卡死、不过热。相机不可用时仍可访问普通任务清单与手动求助；识别错误可修正；模型超时可重试且不丢任务；第一层提示不直接给最终答案。语音指令需覆盖求助、播报、暂停、任务确认与结束，错误识别可重说或改用触控；到期数据自动删除。记录摆放检查通过率、题目定位和识别纠错率、每会话误提醒次数、孩子获得提示后继续作答率、家长复核耗时、语音误触发率、视频可读性、标注对齐、直播接通率、响应时间和单次成本，再决定扩大范围。

## 7. 验证与落地顺序

1. **设备与网络可行性验证**：在小米 Pad 6 上同时运行纸面预览、本地变化检测、事件截图、语音提示与一次 WebRTC 直播；用另一部 Android 手机跨 Wi-Fi／蜂窝网络测试 TURN 回退、文字可读性、发热、耗电及通话回声。验证失败时先调整采集方案，不进入完整业务开发。
2. **双 App 基础闭环**：完成家庭账号与设备配对、粘贴文字导入、任务同步、进入作业前的纸面检查、按事件分析与语音求助、作业结束反馈、家长确认和日报，再用三个年龄段的真实家庭作业检查教学质量。
3. **远程指导闭环**：完成无需孩子再次确认的按需直播、纸面画圈、双向语音、明确的开始／结束状态与失败恢复；按试点数据调整画质、标注对齐、语音体验和成本。

各阶段完成后回写实测结果与接口契约，讨论确认后再开始相应实现。

## 8. 尚需验证的细节

1. 小米 Pad 6 的实际 Android 版本、相机性能，以及按住说话与家长通话的耗电和回声情况。
2. 幼儿园、小学、初中各一份真实家庭作业样本，供题目识别和分年龄引导验收。
3. 第三方模型服务商能否满足裁剪图处理范围与60 天数据保留要求；家长本人视频不列入当前首版。

双端应用与服务端已具备试点构建；设备验证、真实作业样本评测和第三方服务条款核查仍按[实现复盘](implementation-review.md)继续。
