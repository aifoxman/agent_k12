# MVP 实现复盘与下一轮优化

持续更新的优先级与验收标准见[待优化功能清单](optimization-backlog.md)。

## 已完成的核心闭环

家长注册家庭、用 8 位码绑定平板、逐行粘贴群作业；孩子主动开启相机，视觉模型确认纸面清晰后进入作业；平板本地比较低分辨率画面变化，待画面稳定后按事件上传内存中的前后裁剪 JPEG，分别记录进度、书写和可见步骤的候选观察；孩子框选题目按需获得最多三层提示，也能口述或输入自己的思路，文本以孩子自述身份保存；家长按需直接打开 WebRTC 直播，画圈标注并发起双向语音；孩子暂停或结束时停止采集；孩子提交最终截图、家长核对确认，日报汇总并可纠错。API 提供家庭权限隔离、60 天数据清理与提前删除。

## 设计调整

| 发现 | 本版处理 | 下一轮验证 |
| --- | --- | --- |
| 自动判“不会做”容易误伤 | 停笔五分钟只询问是否要提示；每次静止最多一次，可关闭 | 统计误提醒与忽略率，按年龄调整阈值 |
| 直接给答案会削弱独立思考 | 模型默认只给一步提示，回答不清时要求重试或找家长 | 用真实作业样本检查提示是否泄露答案 |
| 直播与 AI 同时占用摄像头 | 同一个视频轨同时用于本地预览和按需 WebRTC 推流 | 小米 Pad 6 上测帧率、温升、续航与长时稳定性 |
| 标注位置可能随画幅变化漂移 | 两端按实际视频宽高调整预览比例，归一化坐标发送 | 真机跨手机尺寸核对对齐；必要时传视频变换矩阵 |
| 语音识别误触发 | 按键说话、触控保底；语音结束会话需二次口令 | 测试儿童发音、噪声和无障碍使用 |

## 仍需补齐的能力

1. **题目定位与教学评测**：当前框选题目可用，“指向题目说这题”尚未做。需要分别收集幼儿园、小学、初中真实作业，量化识别率、提示正确率和泄题率，再决定是否做手势定位。
2. **远程可靠性**：跨蜂窝网的 TURN 回退、断线重连、摄像头被系统回收、来电打断和通话回声尚未实测。试点前必须使用小米 Pad 6 与一部 Android 手机完成同网和异网测试。
3. **家长与孩子的可控性**：目前家长可直接查看，孩子端持续显示查看/通话状态并能暂停。下一轮应加入清晰的异常网络恢复提示、主动提醒开关的家长配置和更细的模型纠错说明。
4. **服务运营**：当前 SQLite、单进程 WebSocket 房间和内存中的实时连接适合小规模试点。多进程部署前需要持久化信令/消息总线、统一限流、监控与备份恢复演练。
5. **隐私供应商核验**：需拿到第三方模型对图像留存、训练使用和删除周期的合同承诺，并核查小米设备系统语音识别服务的音频处理条款。60 天保留是本服务默认值，不能替代供应商条款。

## 验收顺序

先用一套真实设备验收纸面摆放门槛、事件上传和会话反馈；再验收家长蜂窝网直播、圈画及双向语音；最后以三个年龄段各一份真实家庭作业评估教学内容。每轮记录误提醒次数、识别纠错率、连接成功率、提示后继续作答率与家长复核耗时。
