# 外接 UVC 相机

孩子端通过原生 UVC API 把 USB 相机接入作业画面。当前依赖为 `com.herohan:UVCAndroid:1.0.13`，只打入孩子端 APK；家长端不注册 `PaperCamera`，也不增加 UVC 依赖。普通浏览器与没有外接设备时继续使用内置相机。

## 连接与使用

1. 用支持数据传输及 OTG 的连接线／转接器连接相机，正常允许系统的相机权限和本次 USB 设备访问。
2. 在首页或暂停页选择“拍摄相机”：默认“自动 · 优先外接”，也可明确选择“USB 外接相机”或“平板后置相机”。正在作业时先暂停，再切换来源。
3. 点“预览相机”调整位置，用“拍照预览”核对文字、页边和方向。“关闭预览”会关相机并返回原页面。
4. 确认取景后关闭预览，点“开始作业／继续作业”，按正常纸面检查进入会话。原有批改仍需正常家长授权。

### 单页竖拍与画面方向

单页作业建议把摄像头转 90°，重新调整距离，使一页纸的四边完整入镜、周围只留少量空白。平板可保持原来的方向。物理取景让单页占据更多像素；仅旋转画面不会提高原有照片的清晰度。

在相机预览中点“旋转画面”，每次顺时针转 90°，直到文字朝上。方向保存在这台平板中；重新打开外接相机时沿用。预览、拍照、上传、家长查看与辅导使用同一份旋转后的视频像素，辅导标记按该照片定位，不单独旋转。

方向应在作业开始前或暂停后调整。纸面检查期间旋转会使旧检查失效，需要重新检查；活动作业中先暂停再调整。相机方向不会改写已保存辅导的题图与标记。

“自动”只在检测到外接设备时优先尝试 UVC；外接设备打开失败或中途断开会显示错误，不会悄悄切到内置相机冒充外接成功。可在暂停后手动选择内置相机。

## 预览与上传的边界

独立 `preview` 状态只开相机，不做纸面视觉检查、后台题目准备、计时或收页上传。“拍照预览”使用当前实际视频帧，只生成本机内存中的预览照片，关闭时清理。它不代表照片已提交、作业已完成或模型已识题。

“开始／继续”进入正常 `setup` 流程后，才会发送纸面检查；检查通过后建立或恢复会话，后续观察、求助、收页与批改按各自原有流程执行。因此需要零模型调用的取景测试时，应使用“预览相机”，不要用“继续作业”代替。

## 原生与前端接口

- `PaperCamera.open()`、`status()`、`close()`：孩子端 JavaScript 桥返回 JSON；`status` 包括 `supported`、`attached`、`permission`、`state`、`generation`、`frame_id`、尺寸、帧龄与错误信息。权限已允许不等于画面已就绪；首个有效 JPEG 到达后才进入 `streaming`，前端解码首帧后才提供视频轨道。
- `/native-camera/frame.jpg?generation=...`：仅在 App 自身的 `https://appassets.androidplatform.net` 来源提供内存 JPEG，响应禁止缓存。代次不符返回 409；关闭、拔出或超过 2.5 秒没有新帧时返回不可用，不提供旧图。画面字节不通过 JavaScript 桥传递。
- `openCameraSource` 将这些实际 JPEG 连续绘入本机 canvas，再经 `captureStream(10)` 接入现有 `<video>`、截图与家长 WebRTC。此处 canvas 是真实 UVC 视频适配，不是验收静态照片模拟。保持一条视频轨道、零音轨，`data-camera-source` 明确标为 `uvc` 或 `builtin`。
- UVC 原生链路只采集视频，不创建录像或录音组件，也不输出 USB 音轨。App 原有按住说话、通话和家长授权设置保持独立。

原生只选择相机实际公布的模式：宽度 1280–1920、高度 480–1440 像素，优先 1920×1080 MJPEG。协商成功仍不等于视频已启动：同一次打开最多尝试优选模式、1280 像素宽 MJPEG、1280 像素宽 YUYV，兼容候选按原画面比例选择已有高度，不编造设备规格。每个模式等首帧最多 4 秒，总打开上限 20 秒；首帧到达后停止切换，仍无有效画面就明确报错。旧尝试的回调与编码不能发布到新尝试；模式切换清理预览及渲染资源，继续复用本次 USB 连接。支持自动对焦时延迟启用并读取设置状态，保持原有曝光策略。低于支持范围、解码失败或系统 WebView 缺少必要视频接口时会提示错误，不拉伸低清图冒充高清。

暂停、关闭预览和真正离开前台会释放 UVC、停止轨道并使旧帧失效；权限对话框与真正后台分开处理，晚到的编码或旧连接不能发布到新代次。原生相机与 USB 原始连接由当前代次持有，在同一工作线程依次清理。拔插后需要明确重新打开。上述均为实现约束，具体相机、资源释放和系统兼容性仍以现场记录为准。

## 无线 ADB 与 API 重连

外接相机占用 USB 接口时，可先在 Pad 开启“无线调试”，电脑与 Pad 接入同一可信网络。在仓库根目录执行；配对码按终端提示现场输入，不写入脚本或文档：

```powershell
$adbPath = Join-Path $PWD '.tools/sdk/platform-tools/adb.exe'
& $adbPath pair 'PAD_IP:PAIR_PORT'
& $adbPath connect 'PAD_IP:CONNECT_PORT'
& $adbPath devices -l
& $adbPath -s 'PAD_IP:CONNECT_PORT' reverse tcp:8003 tcp:8003
```

配对端口与连接端口不同，实际以 Pad 当次显示值为准；`-s` 使用 `adb devices` 中已连接的完整 serial，也可使用已连接的 mDNS transport 名。调试版 App 的本机 API 地址仍为 `http://127.0.0.1:8003`；正式部署使用 HTTPS 服务地址。

设备或无线连接重建后须重新核对 reverse；需要持续恢复时运行：

```powershell
.\scripts\keep-adb-reverse.ps1 -Port 8003 -Serials 'PAD_IP:CONNECT_PORT'
```

该脚本恢复已连接设备的端口映射，不代替无线配对或连接。网络不通与相机权限失败应分别排查。重装使用同包名的覆盖安装并保留数据，不要卸载或清除 App 数据来排查相机，以免丢失设备配对；隔离验收切换账户前须将原存储备份到私有目录。

2026-10-26 晚间真机出现过清理最近任务后无法重新启动：旧进程的 `paper-uvc-contr` 线程处于内核 `D` 状态，主线程已退出，系统仍将新启动关联到旧进程。此时先拔下 USB 摄像头，保留 Wi-Fi 与解锁状态，再启动 App；确认首页正常后重新接回摄像头。本次拔下后旧线程消失，同一安装包恢复冷启动，随后两轮预览、关闭与重开均成功，关闭后 USB 句柄归零。
