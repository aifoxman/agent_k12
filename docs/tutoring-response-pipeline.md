# 辅导响应与验收

## 圈画到讲解

1. 即时读题使用逐题 JSONL；每题完成即写入稳定 ID、题干、答题区、字词位置和读题缓存。`reading_ready`、`anchors_ready`、`solution_ready` 分开报告，客户端索引不包含后台答案。
2. 手指落下时固定原始相机帧，随后圈画和辅导共用该帧。停止圈画 450 ms 后开始选题；按线段落入题干及答题区的长度比例计分，接近的候选由孩子点选。
3. 旧扫描与新截图先做本地图像配准，再检查整页和题干内部的像素一致性。位置校验失败时走重新定位；相同题号和粗略页面指纹不能直接许可圈画。
4. 后端复核题目所属会话、配置版本、参考图哈希、变换及圈画归属。通过后立即返回缓存读题，同时复用或提速已有求解，独立补齐原题锚点。
5. 当前步骤的可靠文字、草稿先显示，再等待本句语音；后续步骤仍按播放队列推进。慢速锚点不会阻塞思路，迟到的可靠读题标记仅补画，不重复播报。

有已核验解法时，读题同时在草稿展示一条不含答案的入手提要，不增加交互回合。进入完整解答时，保留同一道题已讲出的圈画和草稿，直到新讲解开始；换题不沿用。

答题区包括扫描明确给出的区域。若同一栏下一道可靠题目限定了书写空白的下边界，也纳入该空白；不跨栏扩张，不推测最后一题以下的区域。

## 边界与取消

- 页面移动只在配准和局部像素复核同时可靠时复用内容。曲面变化、严重遮挡、换页或出画时保守回退。
- 暂停、切换相机、切题和离开辅导会取消旧播放与请求；旧圈画、旧草稿不能出现在独立作业状态。
- 圈出的条件表示已知信息，不代表孩子答对。答案确认仍需要独立解题核验。
- 主动求助保持原有语义：同意或 20 秒未回应进入辅导，明确拒绝则继续独立作业。

## 复核方法

构建、自动测试及 APK 发布使用 `.github/workflows/android-build.yml`。覆盖本地选题、跨题歧义、答题区、平移与透视数学、换页拒绝、逐题发布、任务提速、慢锚点并行，以及空白、偏移、低对比度和锐化字词框。

Pad 后摄实测需记录 `paper-teaching-timing` 事件和实际 DOM 出现时间，分别核查固定截图、原题关键词、草稿、首个语音包及续讲完成。缓存命中目标是笔画结束后约 2–3 秒出现有效读题与强调；当前可靠步骤的呈现应不再受 TTS 首包限制。冷扫描、大模型定位和网络超时须单独记录，不能当成缓存命中结果。

作业照片、详细模型输出、调试日志及数据库备份保存在忽略目录 `output/acceptance/`；文档和提交中不保存学生截图、口令或服务凭据。
